PART 1

The "Why" & The Types of Databases

Why do we need a Database? (Without vs With)

Without a Database: Imagine storing all user data in a `.txt` or Excel file. Only one person can edit it at a time. If the server crashes mid-save, the file corrupts. Searching through 1 million rows of text takes forever.

With a Database: A Database Management System (DBMS) is specialized software. Thousands of users can query it simultaneously, it has auto-recovery, and searches take milliseconds.

Relational (SQL) vs. Non-Relational (NoSQL)

Relational (SQL)

  • Examples: MySQL, PostgreSQL.
  • Analogy: A Strict Filing Cabinet.
  • Structure: Strict Tables with Rows & Columns (like Excel).
  • Rule: If a table needs 'Name' and 'Age', you CANNOT insert a record with 'Favorite Color'. It rejects bad data.
  • Best for: Financial systems, strict inventory, where accuracy is critical.

Non-Relational (NoSQL)

  • Examples: MongoDB, DynamoDB.
  • Analogy: A Flexible Magic Box.
  • Structure: Flexible JSON Documents.
  • Rule: You can throw any data into it. User 1 can have 2 fields, User 2 can have 50 fields. It accepts everything.
  • Best for: Social media posts, game data, fast-changing app requirements.

PART 3

The C.R.U.D. Practical Lab

Almost every action a backend application performs falls into four categories: Create, Read, Update, and Delete. Let's build a company database step-by-step.

1. CREATE (Database & Table)

First, we create a Database (the main folder). Then, we create a Table (the sheet inside the folder) with strict rules.

MySQL Shell
-- Create the main database CREATE DATABASE meander_company; -- Tell MySQL we want to work inside this specific database USE meander_company; -- Create a table with 3 strict columns CREATE TABLE employees ( id INT PRIMARY KEY, name VARCHAR(50), department VARCHAR(50) );

2. INSERT (Adding Data)

Now let's add 3 employees into our new table.

MySQL Shell
INSERT INTO employees (id, name, department) VALUES (1, 'Rahul', 'DevOps'); INSERT INTO employees (id, name, department) VALUES (2, 'Priya', 'Frontend'); INSERT INTO employees (id, name, department) VALUES (3, 'Amit', 'DevOps');

3. READ (The SELECT Command)

How we ask the database to show us information.

MySQL Shell
-- Show me EVERYTHING (*) inside the employees table SELECT * FROM employees; -- Show me ONLY the names of people who work in DevOps SELECT name FROM employees WHERE department = 'DevOps';

4. UPDATE (Modifying Data)

Rahul got promoted to a Manager role. We need to update his record.

MySQL Shell
UPDATE employees SET department = 'Manager' WHERE id = 1; -- Verify the change SELECT * FROM employees;

5. DELETE (Removing Data)

Amit left the company. We need to remove his row.

MySQL Shell
DELETE FROM employees WHERE name = 'Amit'; -- Verify he was removed SELECT * FROM employees;

6. EXIT

MySQL Shell
-- Leave the MySQL shell and return to regular Ubuntu exit;

The Danger Zone

In SQL, if you forget to write the WHERE clause on an Update or Delete command, it will apply to EVERY SINGLE ROW in the table!

-- If you type this: UPDATE employees SET department = 'Fired'; -- You just fired your entire company because you forgot to specify "WHERE id = 3"!
